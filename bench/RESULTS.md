## Scenarios

The same data shape for every library, objects that reject undeclared keys everywhere, and every error collected (no library stops at the first one).

- **Small flat object** (`flat`): `{ name: string (minLength 3, trimmed), email: email (trimmed, lowercased), age: integer >= 0 }`. 3 rules broken in the invalid input.
- **Nested user (address, 5 tags max, 10 addresses)** (`nested`): The flat user plus `address: { street (trimmed), zip (minLength 5) }`, `tags: string[]` (`maxItems 5`) and `addresses: Address[]` with 10 items. 7 rules broken in the invalid input, in different places.
- **API request body (an order with 5 items)** (`api-payload`): An order: `cartId` (uuid), `status` (one of four), `customer { name, email, phone? }`, `shipping { street, city, zip, country }`, `items[5] { sku, name, quantity, price }`, optional `coupon` and `notes`, `placedAt` (date-time). Names, street and city are trimmed, the email is trimmed and lowercased. 8 rules broken in the invalid input.
- **List of 1,000 items** (`large-list`): `{ items: Array<{ position: integer >= 0, label: string (minLength 1, trimmed), active: boolean }> }` with 1,000 items. In the invalid input 10 of them break 2 rules each.
- **Union of 4 variants (12 events)** (`union`): `{ events: Event[] }` with 12 events, where `Event` is `click { x, y }`, `view { url, durationMs }`, `purchase { orderId, amount, currency }` or `signup { email, plan }`, told apart by `type`. No transforms. 3 events broken in the invalid input.
- **6 levels of nesting** (`deep`): `{ name: string (minLength 1, trimmed), count: integer >= 0, child: { ...the same, 6 levels deep } }`. 4 rules broken in the invalid input, at levels 1, 3 and 6.
- **Small flat object, checks only** (`no-transform`): The flat object with no trim and no lowercase: `{ name: string (minLength 3), email: email, age: integer >= 0 }`. Nothing is transformed, so every library runs its fastest path.

## What CI holds

`bun run bench:guard` times `blueprint.safeParse` and Zod 4 safeParse on every case above, several times each in one process, and fails when the best time of afora is over the limit of the case, as a multiple of the best time of Zod 4. The limit is 1.15x, except:

- `large-list valid`: 1.25x. afora is level with Zod 4 here (about 1.0x): freezing 1,000 objects and their array is most of the time. The limit is that plus noise.
