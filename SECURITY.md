# Security policy

## Supported versions

afora is in `0.x`: only the latest published version of `@afora/core` and of each `@afora/*` package receives security fixes.

## Reporting a vulnerability

Do not open a public issue. Report it privately through [GitHub's private vulnerability reporting](https://github.com/afora-framework/core/security/advisories/new), with:

- the affected package and version;
- what an attacker can do, and under which conditions;
- a minimal reproduction, if you have one.

You should get a first answer within a few days. Once a fix is published, the advisory is disclosed with credit to you, unless you ask otherwise.

## Scope

Of particular interest: sensitive values (a `sensitive` property such as `Password`) leaking through `toJSON()`, outputs or errors; password hashing and verification; validation that can be bypassed (undeclared keys, reserved keys, prototype pollution); and code generated by `@afora/codegen` or exposed by `@afora/mcp` and `@afora/hono`.
