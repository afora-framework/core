# Brand

How afora presents itself: the line, the words and the colors. For anyone who writes about afora, a page of these docs, a package README or a post, and wants it to sound like the rest.

## The line

**Simple to write. Built to hold.**

- _Simple to write_ is the experience of whoever writes the code, a person or an agent: a few declarations, types that follow the model, an `afora.json` that is the whole application.
- _Built to hold_ is the promise: the guarantees live in the runtime, not in the discipline of whoever writes the code, so they hold when the code is written in a hurry or by an agent.

The technical line under it: **Model the domain; the runtime keeps the invariants.**

## The name

_Afora_, in Portuguese, is "throughout, the whole way" (_mundo afora_, all across the world). The guarantees of afora hold the whole way: from the body of a request, through the record, the repository and the use case, to the response.

## Voice

The docs are written plain and precise, with one name for one thing (see [About these docs](site.md)). The brand is the same voice, a little warmer:

- **Calm.** State what afora does and let the code show it. No "blazing", "revolutionary", "10x", "magic" or exclamation marks.
- **Precise.** A claim names what it covers: "faster than Zod 4 on most of the fourteen cases", not "faster".
- **Honest.** Say where afora loses (bundle size, compiled checkers, ecosystem) next to where it wins. That honesty is part of why the guarantees are believed.
- **For both readers.** Every page is read by people and by agents: concrete names, code that runs, no meaning carried only by an image.

The gradient of the banner's highlighted word, and of afora's bar in the chart, goes sage, amber, orange. Headlines are set in IBM Plex Sans, code and captions in IBM Plex Mono.
